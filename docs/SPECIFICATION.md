## 1. 原則・互換性

BCMはCommonMarkにGFMの表、取り消し線、タスクリスト、自動リンク等を追加し、その上に宣言的な書籍制作用ディレクティブ、数式、脚注を追加する。標準Markdownの見出し・段落・画像・コード・表等は、個別の拡張機能を使わない限り書き換えない。テーマ適用、番号付け、ページ分割等の派生結果は原文に記録しない。生HTML、未知記法を保存できることと安全に描画できることは別であり、任意コード実行を許可しない。

BCMの有効化は呼び出し側が明示する形式モードに従う。BookCreatorではプロジェクトの明示的な形式設定（book.yamlの文書形式バージョン、正式キーは本体のPROJECT_FORMATで確定）から指定する。ライブラリはbook.yamlや特定アプリの存在を必須としない。一般Markdownを読み込む際は原文を維持し、BCMとして再解釈する場合の意味の変化を事前に診断する。インポートだけで拡張記法への変換は行わない。通常Markdownの外部ビューアで拡張部品が完全に表示されることは保証しない。互換性のため、長い本文は可能な限り通常Markdownとして残す。一般Markdownへの書き出しを提供する場合は別の派生出力とし、損失箇所を提示する（初期製品の必須範囲とはしない）。

新規ファイルはUTF-8/LF。既存UTF-8ファイルのBOM・CRLF・混在改行を保持する。未対応エンコーディングは誤変換せず、読み込み/明示変換の判断を求める。アプリのバージョンと文書形式のメジャーバージョンは独立。未知の必須形式バージョンでは原文の閲覧・退避を可能にするが、意味を変更するGUI編集・出版を停止する。

## 2. 基本文書モデル

| 種別 | 原文 | 内部モデル |
| --- | --- | --- |
| 通常の本文 | CommonMark/GFM | paragraph, heading, list, table, quote, thematicBreak等 |
| インライン | emphasis, strong, link, inlineCode等 | 文字列・意味・範囲を持つノード |
| コード | フェンスまたはインデントコード | 言語ID、原文、行構造 |
| 標準画像 | ![alt](path) | 画像参照、alt、任意title |
| BCM拡張 | directive, math, footnote | 構文種別、属性、子、原文範囲 |
| 未対応・未完成 | 原文そのもの | opaque / invalid node、診断 |

原文が正本。ASTは意味モデル、CST相当のトークン/範囲は書き戻し用。ASTだけから原稿全文を再生成しない。各ノードは原稿ファイルID、revision、半開区間[start,end)のUTF-16コード単位位置を持つ。UTF-8のバイト位置、ユーザーに見せる行/列（1始まり）、エディタ固有の位置は変換テーブルを用いて区別する。サロゲートペア、結合文字、絵文字、CRLFを分断する編集を拒否する。文書内の一時nodeKeyは永続IDと別物であり再解析で変化し得る。

セクション（book.yamlの出版順上の単位）と章（設定された見出し階層）は独立。文書ファイル境界は既定で改ページするが、文法上の意味を変えない。continuousの先頭の部品開始条件抑制は組版側で処理する。

## 3. ディレクティブ構文

### 3.1 3種類

    :ref{target="fig-unity" format="label-number"}

    ::pagebreak{side="any"}

    :::callout{kind="tip" title="ポイント"}
    通常のMarkdown本文をここに書く。
    :::

- インライン: コロン1個 + name + 属性ブロック（必須）。既定でラベルを生成する。インラインディレクティブは段落等のインライン構文として扱い、リンクの宛先、コードスパン、数式の中などでは解析しない。
- 単独ブロック: コロン2個 + name + 属性ブロック（必須）。行の残りは空白のみ。前後は空行または文書/コンテナ境界を要求する。
- コンテナ: コロン3個以上 + name + 属性ブロック（必須）。開始行と対応する閉じ行の間に内容を保持する。閉じ行は開始と同数のコロンと任意の末尾空白のみ。コンテナの外側には空行または文書/親コンテナ境界を置く。内部の開始/終了行に隣接する本文はコンテナ境界として扱う。属性のない場合も {} を書く。
- nameは小文字ASCIIで始まる英数字と単一のハイフン区切り。例: figure, pagebreak, my-note。大文字、末尾ハイフン、空白は許容しない。
- 当初はブロックディレクティブの開始/終了行をファイルまたはBCMコンテナ本文の行頭（インデントなし）に限定する。通常Markdownのリスト、引用、インデントコードの字下げと混同しないためである。リスト・引用内部への複雑なBCMブロックの拡張はPoC後に検討する。通常のインライン拡張は対象のインライン文脈で利用できる。
- インラインの認識は未エスケープのコロンから開始し、nameと直後の{が続く場合に限る。直前がASCII英数字、アンダースコア、コロンのときは認識しない（時刻・URI等との衝突回避）。和文に隣接した参照は可。GFMの自動リンク等のトークン内に侵入しない。
- コロンをバックスラッシュでエスケープすれば通常文字になる。ブロックディレクティブを文字として表示したい場合は最初のコロンをエスケープするかコードとして記述する。
- remark/unifiedと既存directiveプラグインを候補とするが、以下のBCM規則がそのまま成立するとは仮定しない。相違箇所は独自拡張またはパーサーで処理する。採用判断はPoCで行う。

### 3.2 入れ子と閉じ規則

    ::::layout{split-policy="avoid"}
    ## 見出し

    :::callout{kind="tip"}
    説明文です。
    :::

    ::::

外側のコロン数は内側の開始フェンスより大きくする。閉じは現在の開いているコンテナと同じ長さのみを認識する。コードフェンス、インデントコード、HTMLブロック、数式等の保護された内容に現れる文字列は閉じ記号にしない。外側と同数以上の開始フェンスを入れ子にすること、不整合な閉じフェンス、EOFまで閉じない場合は構文診断とする。原稿は保存できるが、誤って後続本文を欠落させないため正式/試し出力を停止する。通常のコロンだけの行は有効な開きがない限りMarkdown本文として扱う。GUIの生成する外側フェンスは内部フェンス最大長より1以上長くする。

### 3.3 属性ブロック

属性は一行。以下は概念文法（EBNF相当、正式な字句解析テストで固定する）。

    attributes = "{" wsp* [attribute (wsp+ attribute)* wsp*] "}"
    attribute  = id-shorthand | key "=" quoted-value
    id-shorthand = "#" identifier
    key        = lower-name
    quoted-value = '"' (ordinary | escape)* '"'
    escape     = '\\' ('"' | '\\' | 'n' | 't' | 'r' | 'u' hex hex hex hex)
    wsp        = ASCII space or tab

ordinaryは改行・制御文字・ダブルクォート・バックスラッシュを除くUnicode文字。波括弧を引用符内で使用できる。エスケープはJSON文字列に近い上記の限定集合。Unicodeエスケープの孤立サロゲートは拒否。属性キーと値の間の空白、単引用符、未引用値、カンマ区切り、class短縮記号は初期構文では許容しない。IDは1ブロックに1つ。属性キーの重複、#idとid属性の併用、未知エスケープ、未閉じ引用符は診断する。明示id属性は使用せず#idに統一する。キー順に意味はない。元から存在する順番・空白・引用値は変更対象以外保持する。

すべての属性の字句値は文字列。型変換はディレクティブの登録スキーマで決める。true/falseは小文字のみ、整数は符号なしまたは型で許可された符号付き10進数、実数は有限10進数（指数表記は初期非対応）。NaN、Infinity、型の暗黙変換、桁あふれを拒否する。配列・オブジェクトを単純属性に暗黙埋め込みしない。複合データは型付きCanvas宣言等の専用構文を利用する。

### 3.4 構文優先順位

1. 通常Markdownのコード・エスケープ・リンク宛先・生HTML等の保護領域を認識する。
2. BCMコンテナ/単独ブロックとブロック数式、脚注定義の境界を識別する。通常Markdownの解析を任意の行で壊さない。
3. 保護領域外の通常インライン、数式、脚注参照、BCMインラインを解析する。
4. 属性型、子要素の構造、位置制約、参照、テーマ依存を検証する。

これは論理上の優先順位であり、単純な正規表現で全文を置換する実装を要求しない。構文競合のある入力はfixtureとして固定する。

## 4. 共通属性の型と意味

| 型 | 例 | 制約 |
| --- | --- | --- |
| boolean | "true" | true/falseのみ |
| integer | "3" | 各属性で範囲指定、有限 |
| length | "5mm", "14pt" | 単位必須、通常余白は非負 |
| proportion | "75%" | 配置先の利用可能幅が基準。幅は0超100以下を既定 |
| size keyword | "auto", "fill" | 許容属性に限定 |
| enum | "center" | スキーマ列挙 |
| text | "Unity Editor" | Unicode文字列、HTMLを実行しない |
| reference | "fig-unity" | 安定ID、参照先種別を検証 |
| path | "../assets/image.png" | 宣言元ファイル相対。範囲検査 |

1in=25.4mm=72pt。内部では固定の物理単位で計測し、丸め規則はCOMPONENT_SYSTEM/LAYOUT_ENGINEで定義する。画面pxを正本としない。画像のwidthのautoは明示指定時に自然寸法を部品・利用可能領域の規則で解決する。属性省略はテーマ既定値を継承し、明示autoとは区別する。heightのautoは比率維持。%による高さは基準高さが未確定になりやすいため初期の原稿属性では非対応（固定Canvas内は部品スキーマで別規定）。幅と高さの両方を指定する場合はfitを適用する。個別の負余白や画面ピクセル単位は初期非対応。

共通ブロック上書き（対応する種別のみ）:

| 属性 | 型/値 |
| --- | --- |
| variant | テーマ内のバリアントID |
| start-position | flow / page-top / spread-start-top / spread-end-top |
| split-policy | allow / avoid / strict |
| keep-with-next, keep-with-previous | boolean |
| min-following-space | length |
| margin-top, margin-bottom | 非負length |
| margin-left, margin-right または margin-inner, margin-outer | 非負length。両系統の混在禁止 |
| margin-at-page-top, margin-at-page-bottom | keep / suppress |
| align | left / center / right / inner / outer / stretch（種別ごと制限） |
| width | length / proportion / auto / fill（種別ごと制限） |
| font-size | 正のlength（pt/mm） |

BCMの属性名はkebab-case、テーマの型名/プロパティとの対応はCOMPONENT_SYSTEMに一意に定義する。以前の例のspace-beforeはmargin-topに統一する案。新規の未公開形式であるため現時点では互換別名を増やさない。個別上書きは「属性なし＝継承」であり、無効化は属性削除または明示値の選択。属性を編集してもテーマ側は変更しない。互いに矛盾する属性や適用不可の属性は診断し、推測で片方を消さない。

## 5. 標準ディレクティブ

### 5.1 改ページ・空白ページ

| 構文 | 属性 | 意味 |
| --- | --- | --- |
| ::pagebreak{side="any"} | side=any/left/right、既定any | 明示的なページ開始 |
| ::blank-page{count="1" numbered="false"} | count=正整数（既定1）、numbered=boolean（省略時区間規則） | 意図的な実空白を追加 |

pagebreakは原稿のルート（ファイル直下）の有効なブロック境界で使用する。現在がページ先頭ならanyで空白を追加しない。左右は内頁面で評価し、実空白が必要なら派生生成する。隣接anyは二重改ページを発生させない。blank-pageは明示された枚数の実ページを占有する。numberedは印字可否の上書きであり番号区間のcountBlankとは別。数えないページには印字しない。手動pagebreakとblank-pageの操作はUndo可能。生成された境界を自動でディレクティブに変換しない。continuousの先頭条件抑制はこれらの明示指示を無効化しない。

### 5.2 画像 figure

    ::figure{#fig-unity src="../assets/unity-editor.png" alt="Unity Editorの画面" width="75%" align="center" caption="Unity Editor"}

| 属性 | 値・意味 |
| --- | --- |
| src | 必須。ローカル素材への相対パス |
| alt | 代替説明。空文字は明示的な装飾画像として扱う |
| caption | 任意のプレーンテキスト。改行はエスケープで指定可能 |
| title | 任意の補足情報。標準Markdown画像のtitle移行用 |
| width / height | 幅はlength/%/auto/fill、高さはlength/auto |
| align | left/center/right/inner/outer/stretch |
| fit | contain/cover/stretch。既定はテーマ、未設定ならcontain |
| crop-x, crop-y, crop-width, crop-height | 正規化座標0〜1。全4属性を一組として指定 |
| rotation | 初期は0/90/180/270度 |
| numbered | boolean。省略時は書籍の採番設定 |
| 共通属性 | 適用可能なもの |

クロップは元画像のEXIF向きを正規化した座標系、左上原点、右・下正。crop-width/heightは正、x+width及びy+heightは1以下。クロップ→回転→fitの順を基準とする。元画像を変更しない。alt省略は診断候補であり、意図した空altと区別する。GUIが標準画像をfigureへ変換する際はalt/title/参照を維持する。段落中に文字と混在するインライン画像を無断でブロックfigureに変換しない。変換が必要なら前後本文の分割と差分を提示する。リファレンス形式画像の共有定義を一画像の調整だけで変更しない。

自動図番号はcaptionに含めず、番号スロットで表示する。既存の手動番号を入力した場合は文字列を推測して削除しない。

### 5.3 layout — 既存Markdownブロックの属性付与

    :::layout{#sec-variables start-position="page-top" numbered="false"}
    ## 変数の使い方
    :::

    :::layout{#example-score split-policy="avoid" caption="スコアの加算"}
    ~~~csharp
    int score = 100;
    score += 10;
    ~~~
    :::

layoutは通常Markdownの既存ブロックを包み、内容の意味を変えずに属性を付ける。本文必須。子が1ブロックなら外側の永続IDをその子の意味的参照IDとして扱う。子が複数ならIDはグループを示す。子が既に同じ意味の永続IDを持つ場合は重複する参照ID付与を拒否し、既存IDを利用する。captionは単一の表/コード/数式等、numberedは単一の番号対象にだけ適用可能。複数ブロックのグループにcaptionを指定して図番号等を勝手に割り当てない。共通ブロック上書きはグループ境界の規則となり、子の意味構造・見出し階層は保持する。ページ番号区間用の参照はルートの有効な境界に対応するIDのみを使用できる。

### 5.4 callout / component

    :::callout{kind="tip" title="ポイント"}
    **名前**は役割が分かるものにしましょう。
    :::

    :::component{name="exercise" #ex-01}
    次の問題を解いてみましょう。
    :::

calloutのkindはテーマのバリアント（既定候補note/tip/warning/important）。titleはプレーンテキスト。componentのnameは登録済み部品IDを指定する必須属性。部品のスキーマによって追加の型付き属性を許可する。任意HTML/CSS/JavaScriptを属性として実行できない。

既定本文スロットは通常Markdownの子ブロック。複数の名前付きスロットが必要な部品はslotコンテナを用いる。

    ::::component{name="exercise"}
    :::slot{name="question"}
    次のコードの出力を答えなさい。
    :::

    :::slot{name="answer"}
    100が出力されます。
    :::

    ::::

上例では各slotを:::、外側を::::で閉じる。slotはcomponent直下専用。スロット名・型・必須/任意・最大出現数・描画順は部品スキーマによる。未知スロット・不足スロットを勝手に捨てない。明示slotと既定本文の混在は、部品が既定スロットを持ちかつ許容する場合に限る。番号・見出し・参照の順序は意味的な文書順を基準とし、装飾用の重なり順と区別する。

### 5.5 canvas — 自由配置

外部ファイル:

    ::canvas{#unity-diagram mode="flow" src="../layouts/unity-diagram.yaml"}

    ::canvas{#chapter-opening mode="spread" src="../layouts/chapter-opening.yaml"}

インライン:

    :::canvas{#small-card mode="flow"}
    ~~~yaml
    schemaVersion: 1
    root:
      id: root
      type: canvas
      width: 80mm
      height: 35mm
      children:
        - id: title
          type: text
          x: 5mm
          y: 5mm
          text: "Unity"
    ~~~
    :::

mode=flow/page/spread。flowは不可分の通常ブロック、pageは一面、spreadは二面の固定見開き。modeは配置インスタンスの属性でありCanvas宣言と重複させない。page/spreadはルートのみ、内部座標や用紙寸法の契約はCOMPONENT_SYSTEM/LAYOUT_ENGINEで定める。外部参照はsrc必須・本文なし、インラインはsrc禁止・単一のyamlコードフェンスを本文として持つ。宣言の完全なスキーマはCOMPONENT_SYSTEMで規定する。例は構造を示すドラフト。YAML内のパスはその宣言元（外部ファイルまたは原稿）相対。外部化/埋め込み時はパスを再計算し、描画意味を保つ。YAMLは安全なデータ部分集合のみ、重複キー・タグ・循環・任意実行を禁止する。

外部ファイルを複数箇所で参照すること自体は可能。GUIで局所編集する場合は共有定義変更か独立コピーかを明示する。同じ配置をMarkdownと外部ファイルに二重保存しない。永続IDは配置インスタンスの識別子であり、Canvas内部ノードIDは宣言内の局所スコープ。

### 5.6 ref / cite / 生成リスト

    :ref{target="fig-unity" format="label-number"} を参照。

    :cite{key="unity-manual"} を参照。

    ::toc{depth="3"}

    ::list-of{kind="figure"}

    ::bibliography{}

refはtarget必須、format=label-number/number/title/page（既定label-number）。参照先に必要な値がないときは診断する。参照元は原稿のテキストとIDだけを保存し、解決した番号は保存しない。未解決時は編集プレビューで明示的なプレースホルダーと診断を表示。正式/試し出力では必要な参照が解決できない状態をエラーとする案。文献引用はkey必須、複数文献はkeys="key1,key2"（keyと排他）、任意のlocator="p. 12"等を付けられる。locatorの複数文献への対応は初期は単一引用に限定。引用キーは書籍単位で一意、コンマと空白を含まない。文献の正本はプロジェクトの文献ファイルであり、具体的形式と引用スタイルはPROJECT_FORMATと組版詳細設計で確定する。

tocのdepthは1〜6、対象は書籍設定による。list-ofのkindはfigure/table/code/equation。bibliographyは指定位置に文献一覧を生成する。初期は同種生成リストを一書籍に複数挿入する場合は診断し、区間別一覧は後続詳細設計で扱う。原稿へ派生リストを自動生成しない。ページ番号参照、目次の収束は組版責務。固定番号やカウンタリセットを原稿に暗黙追加しない。

## 6. 数式・脚注・コード

### 数式

インラインはドル記号1個で囲む。開き直後と閉じ直前は空白不可、閉じ直後がASCII数字の場合は閉じとしない。空の数式、改行跨ぎは不可。通常のドル記号はバックスラッシュでエスケープ可能。金額表記と数式の競合があるため、金額を含む既存Markdownの取り込み時に診断・プレビューする。ブロックは行頭のドル記号2個だけの行で開始/終了し、間のLaTeX互換数式を保持する。閉じられないブロックは診断する。数式内のディレクティブ・Markdownを解釈しない。複雑なTeXや外部ファイル読み込み、任意コード実行は不可。式番号・IDは単一数式をlayoutで包んで付与できる。

### 脚注

    本文の説明です。[^note]

    [^note]: 補足説明です。

脚注はファイル単位の定義/参照スコープを初期案とする（同一ラベルが別ファイルにあっても別脚注）。出版時の番号は書籍または章等の設定された範囲で派生採番し、原稿ラベルとは独立する。未定義・重複定義を診断し、未参照定義を自動削除しない。複数段落の定義は通常の脚注拡張の字下げ規則をPoCで確定。脚注内の改ページ、固定Canvas、脚注の再帰参照は初期非対応。BCMは同じ定義を指すすべての参照を保持し、利用側が文書IDと脚注ラベルに基づく識別子で解決できるようにする。BookCreatorの出版方針Q17では、同一脚注を参照された各ページに同じ番号で表示し、同一ページでは1回のみ表示する。配置・重複排除・分割はLayout Engineの責務であり、独立BCMライブラリのパーサーがページを推測したり定義を複製したりしない。章を跨ぐ脚注の直接参照が必要な場合は別仕様を追加する。

### コード

標準のフェンスとインデントコードを利用。フェンスinfo stringの先頭トークンを言語IDとして解釈し、残りは原文保持（初期は未解釈）。既知言語は構文強調、未知言語は原文のままプレーン表示。行番号・折返し・色はテーマ属性または対応するlayout上書き（詳細は部品スキーマ）。元のインデント・改行・空白を強調処理で変えない。コード内のBCM記法は無効。行番号は論理ソース行であり、表示上の折返しにより増えない。

## 7. ID・参照の契約

永続IDは書籍内で一意。ASCII英字で開始し、以降ASCII英数字・ハイフン・アンダースコア・ピリオドを許容（大文字小文字を区別、長さ1〜128を暫定上限）。予約されたsection:等の名前空間と混同しない。GUI生成は衝突を検査した安定IDを使用する。タイトルやファイル名から自動で再生成しない。ファイル移動・名称変更でIDは変化しない。通常MarkdownにIDは不要。参照/アンカーを初めて作成する明示操作で必要なIDを追加する。

- 複製: 新しい永続IDを生成し、複製範囲内の対象を指す参照も対応する新IDへ更新する。範囲外を指す参照は変更しない。コピー元は変えない。
- 移動: 同一書籍内でIDを維持。素材の相対パスを再計算し、参照先の意味を維持する。別書籍へ移す場合は衝突・未解決参照を検査し明示的に解決する。
- 削除: 参照元一覧を示し、削除後の参照切れを診断する。勝手に別対象へ付け替えない。
- インポート/外部Git編集: 重複IDを検知して診断。無断で一括再採番しない。

文献キー、ファイル内脚注ラベル、部品ID、Canvas内ノードIDは書籍内ブロックIDと別名前空間。章節番号、図表番号、PDF通し位置、誌面番号は派生値であり永続IDの代替にしない。標準Markdownリンクの既存アンカーを永続IDと同一視しない。PDF内部リンク・目次は組版で解決する。

## 8. 素材パスと安全性

相対パスは宣言元ファイル相対、区切りは/。標準Markdown画像・リンクのエスケープとBCM属性の文字列エスケープを区別する。ファイル参照では絶対パス、ドライブ指定、UNC、NUL、URLスキームを拒否する。..は正規化の結果が許可プロジェクトルート内の場合のみ許可し、実ファイルのシンボリックリンク等も検証する。外部URLは通常のリンクとして保持可能だが、画像・フォントのリモート取得は明示インポートのみ。ネットワークアクセスを伴う描画、任意HTML/CSS/JS、危険なSVG、任意YAMLタグを実行しない。ファイル移動時は参照パスを再解決する。Webアダプタでも同じ論理パスと境界を検査する。

## 9. 解析・検証・書き戻し

解析結果は {revision, files, syntaxTree, sourceMap, diagnostics} に相当する契約を持つ。診断はcode、severity、file、range、relatedRanges、message、fix候補（明示適用のみ）を持つ。構文、型、構造、参照、依存関係、組版エラーを区別する。

| 状態 | 保存 | GUI | 出版 |
| --- | --- | --- | --- |
| 正常 | 可 | 対応範囲を編集可能 | 組版検査に従う |
| 未知属性/ディレクティブ | 原文保持 | 未知部分はopaque表示 | 意味や表示の欠落が不明なら停止、既知の非必須装飾のみ警告可 |
| 不完全/不正構文 | 原文保持 | 該当範囲を読み取り専用、旧プレビューを明示 | 停止 |
| 不正パス/参照切れ | 原文保持 | 診断・修正導線 | 必要素材/参照なら停止 |

GUI編集は対象revisionと元範囲・元文字列を検証し、非重複のテキストパッチとして適用する。複数ファイルの変更は一つの論理操作。対象以外のバイト列の不変性をテストする。変更後に再解析して期待した意味・構造が成立しなければGUI操作を取消し、元原文を保持する。ソースの直接入力は不正構文でも保存できる。IME確定前に原文を勝手に整形しない。未知部分を含む親ノードを全体再生成する必要があるときは操作を制限するか明示差分を提示する。属性の挿入、削除、値変更は可能な限り属性トークンだけを変更する。Undo/Redoの正確な状態機械はEDITOR_TRANSACTIONSで定義する。

GUIが新規生成する記法は一貫した属性の引用、単位、フェンス長、空行を使用する。ただし「開く」「保存」「組版」「検査」だけで原稿全体の正規化をしない。明示フォーマット機能は別操作。

## 10. パーサー受入・回帰fixture

| ID | 入力/操作 | 合格条件 |
| --- | --- | --- |
| BCM-01 | 通常Markdown/GFMのみ | BCMの有無で既存意味を変えない |
| BCM-02 | 日本語・絵文字・CRLF・BOM・コメント | 局所変更以外のバイト列不変 |
| BCM-03 | コード内に::pagebreakやドル記号、閉じフェンス候補 | 拡張として解釈しない |
| BCM-04 | 引用符・波括弧・Unicodeエスケープを含む属性 | 復号と原文保持が正しい。不正エスケープを診断 |
| BCM-05 | 重複属性、未知キー、無限大、不正単位、未閉じコンテナ | 診断、原文保持、必要時出版停止 |
| BCM-06 | 長さの異なる入れ子、コード内のコロン列 | 対応する閉じのみ認識 |
| BCM-07 | 標準画像からfigureへGUI変換 | alt/title/path保持、既存画像は無変更 |
| BCM-08 | クロップ・回転・幅・寄せの局所更新 | 属性のみ変更、再読込・Undoで同じ意味 |
| BCM-09 | layout内の単一見出し/複数段落 | IDの意味とグループを正しく区別 |
| BCM-10 | 図の追加・移動・複製・削除 | 参照の安定性と重複/切れ診断、無断再割当なし |
| BCM-11 | 外部CanvasとインラインCanvasの相互変換 | 同じ宣言とパスの意味、二重正本なし |
| BCM-12 | 未知ディレクティブを含む原稿をGUI編集 | opaque部分と未変更範囲を保全 |
| BCM-13 | ページ指示・数式・脚注・引用・目次・コード混在 | 各構文を独立認識、原文保持 |
| BCM-14 | 金額・URL・コード・エスケープされたドル記号 | 文脈に応じ通常文字として維持 |
| BCM-15 | 相対パス・シンボリックリンク・範囲外パス | 正常参照だけ解決、範囲外アクセス禁止 |
| BCM-16 | 古いrevisionのGUIパッチ、IME中の編集 | 誤った原文更新なし |
| BCM-17 | 連続配置の先頭H1と途中H1 | 原稿は不変。組版で先頭のみ部品開始条件抑制 |
| BCM-18 | 数式/脚注/引用を含む複数ファイル | 参照スコープと採番契約を満たし、欠落を診断 |
| BCM-19 | 外部Markdownの取り込み、未知形式バージョン | 無断変換なし。必要なら読み取り専用 |
| BCM-20 | 部品の名前付きスロット | 型・必須・重複を検査し、内容を無断削除しない |

fixtureは実際の入力・期待AST・期待診断・パッチ前後の原文をテスト資産として保持する。パーサーの採用判定にはBCM-01〜20の縮小ケースと基本設計のT04/T06/T18/T19/T74/T81/T84/T85/T95を用いる。まだ合格していない。

## 11. 残る確認・他文書との責務

- PROJECT_FORMAT: 形式バージョンのキー、文献ファイル形式、素材・セクション・出版設定、参照スコープ。
- COMPONENT_SYSTEM: 部品登録の型、スロット型、Canvas宣言、単位・既定値・個別上書き。
- EDITOR_TRANSACTIONS: パッチの実行、位置変換、IME、Undo/Redo、外部変更、復旧。
- LAYOUT_ENGINE: 分割、番号、脚注、見開き、生成一覧、制約競合と収束。
- PDF_EXPORT: ページ計画の固定と出力検査。
- POC_PLAN: 具体的なパーサーライブラリ/独自実装の比較、fixture、性能。

今回の初期案のうち、脚注のファイル単位スコープ、数式と金額の字句規則、ブロックディレクティブのリスト・引用内への対応範囲、文献形式、共有CanvasのUXは実装前に検証・必要に応じてレビューする。既存ライブラリの制約を理由に製品要件を削らず、必要ならBCM専用構文解析を実装する。未決のWeb PDF方式・MIT最終ライセンスを本書で確定しない。
